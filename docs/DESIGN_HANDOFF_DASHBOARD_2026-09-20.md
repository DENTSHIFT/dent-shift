## 1. 最重要事項: 正本画像には未実装の指標が含まれている

視覚的正本として`design/reference/dashboard/`配下の画像があるが、**診断結果画面のときと違い、これらの画像には現在のDBに存在しない・計算していない指標が多数含まれている。** 具体的には以下。

- 前回比の推移を示す折れ線グラフ(「AI表示率・予約推移」)
- 「AI表示率」「公式引用率」のパーセンテージ数値
- 「AI流入」「予約完了」「新患」の件数
- 「商圏競合比較」の棒グラフ(自院・競合A・競合B・競合Cの数値スコア比較)
- 「マルチAIモニタリング」の各AI(ChatGPT/Gemini/Claude/Perplexity/Grok)ごとの稼働状況("良好"等)

これらは実装として存在しない、または意図的に「未連携」と表示している(`src/app/dashboard/page.tsx`のmetricsGrid、`integrationFlow`セクションを参照)。**このプロジェクトには「取得不能値を0や架空の数値として表示しない」「サンプル/mockデータを実績として見せない」という、コードベース全体で一貫して守られている絶対原則がある。** 正本画像に描かれているからといって、上記の未実装指標に架空の数値やダミーの折れ線グラフ・棒グラフを描画することは**禁止**。

**やってよいこと**: 正本画像の「視覚的スタイル」(カードの角丸・影・アイコンバッジの使い方・余白の取り方・サイドバーの配色・全体のレイアウト密度)を取り入れて、既存の「未連携」「連携後に表示」というテキスト表示のコンテナを正本と同じ見た目のカードに載せ替える。

**やってはいけないこと**: 「未連携」の代わりに架空の数値・グラフを表示すること。ステータスバッジ(対応済み/対応中/未対応)のような、実装が無いのに実装があるかのように見える機能を追加すること。

迷ったら数値やグラフは追加せず、既存の「未連携」表示のまま見た目だけを正本に寄せること。

## 4. 現状の実装で確認できている主な差分(2026-09-20、実機確認ベース)

1. **6領域スコアのミニカード**: 正本はAIO/MEO/SEO等に色付きアイコンバッジ(✨📍🔍等)が付いている。現状は「推定」等のテキストバッジのみでアイコンが無い。
2. **サイドバーナビゲーション**: 正本は各メニュー項目に色付きアイコンがあり、視覚的にリッチ。現状もアイコンはあるが簡素。
3. **「営業電話なし・オンライン完結」バッジ**: 正本の左サイドバー下部に常設されている。現状の実装には存在しない。**これはデータを伴わない静的な文言なので、追加してよい(むしろ最重要原則を可視化する良い機会)。**
4. **相談CTAの配置**: 正本ではサイドバー下部に固定表示。現状は左サイドバーの下、メインコンテンツの外に別カードとして存在する(実装済みの`スペシャリストに相談する`カードを参照。配置の微調整は可)。
5. **全体の情報密度・カード間の余白**: 正本の方が密度が高くコンパクト。厳密な差分は着手前に自分で最新スクリーンショットを取って確認すること。

## 5. 動作確認の手順

このリポジトリにはUIコンポーネントのスナップショットテストが無い。**必ず実際にブラウザで確認すること。**

```bash
cd /Users/masatokimura/Documents/dent-shift
npm run dev
```

**注意**: `localhost:3000`が過去に別プロジェクトのdevサーバーと衝突したことがある。`http://127.0.0.1:3000`のようにIPv4を明示してアクセスするか、事前に`lsof -nP -iTCP:3000 -sTCP:LISTEN`で確認すること。`pkill`で無関係なプロセスを巻き込まないよう注意(`pkill -f "next dev"`は`vinext dev`のような無関係コマンドにもマッチする)。

ダッシュボードはログインが必要。既存のClinic/Contactが無ければ`/signup`から作成し、確認後は必ず削除すること(Contact→Session→Clinicの順に削除)。既存の診断結果を紐付けて確認したい場合は、確認後に必ず元の`clinicId`へ戻すこと(diagnosisレコードを他clinicへ付け替えたまま放置しない)。
