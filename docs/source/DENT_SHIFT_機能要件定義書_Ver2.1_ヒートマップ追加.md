## 1. Ver.2の目的

DENT SHIFTを、汎用AIO/LLMO・Web解析製品の単なる歯科版ではなく、歯科医院の「AI検索での発見」から「予約・新患獲得」までを一元管理する専門SaaSとして定義する。

Ver.1の6領域100点診断、改善アクション、制作会社向け指示書を維持したうえで、株式会社ユーザーローカル「User Insight」のAIO/LLMO機能調査から得た以下の機能を統合する。

- 複数LLMでの引用・推薦状況の定点観測
- プロンプト、医院名、ドメイン、競合医院の登録
- AI流入元と閲覧ページの分析
- Google AI Overviewsの引用監視
- AIO/LLMO最適化レポート
- AI記事生成と改善後の再検証
- 段階的なオンボーディング

さらに、DENT SHIFT独自の歯科特化機能、医療広告チェック、商圏競合比較、予約・新患成果計測、営業電話なしのオンライン完結導線を追加する。

## 3. DENT SHIFTの4段階ループ

1. **整理**：医院情報、診療内容、商圏、競合、監視プロンプトを設定する。
2. **調査**：AIO、LLMO、MEO、SEO、予約導線、口コミを診断する。
3. **対策**：優先順位付き改善タスク、記事案、制作会社向け指示書を生成する。
4. **検証**：引用、表示、流入、予約、新患への変化を再測定する。

このループを単発診断ではなく、月次・週次・日次で継続運用する。

## 5. 初期登録・設定

### 5.1 必須入力

- 医院名
- 公式サイトURL
- メールアドレス（Gmail等のフリーメールも利用可能）

### 5.2 任意・契約後入力

- GoogleビジネスプロフィールURL
- Web予約URL
- 主要診療科目
- 強化したい自費診療
- 商圏・最寄り駅
- 診療時間、休診日、院長名
- 比較したい競合医院
- 目標新患数、目標予約数

### 5.3 電話番号方針

- 無料診断、資料取得、契約で電話番号を原則必須にしない。
- 医院代表番号を営業追客に利用しない。
- ユーザーが面談を予約した場合のみ、緊急連絡用番号を任意取得する。
- 画面上に「資料請求後の営業電話はありません」と明記する。

## 6. 監視プロンプト設計

### 6.1 自動生成軸

- 地域：「大阪市淀川区でおすすめの歯医者」
- 駅：「塚本駅周辺で通いやすい歯科医院」
- 症状：「塚本で歯が痛いときに相談できる歯医者」
- 診療：「梅田でインプラントに対応する歯科医院」
- 患者属性：「子どもを連れて行きやすい歯医者」
- 利便性：「仕事帰りに通える歯医者」
- 比較検討：「矯正歯科を選ぶときのポイント」
- 不安解消：「インプラントの費用とリスクを説明してくれる医院」

### 6.2 安全要件

- 医院が提供していない治療を監視対象にしない。
- 「必ず治る」「絶対安全」など不適切な前提を含めない。
- 地域、診療、患者属性の組み合わせを医院ごとに最適化する。
- プロンプトの追加、停止、編集、グループ化を可能にする。

## 7. マルチLLMモニタリング

### 7.1 対象AI

- ChatGPT
- Gemini
- Claude
- Grok
- Perplexity

### 7.2 記録項目

- 医院名の表示有無
- 回答内の位置・推薦順位
- 公式サイトの引用有無
- 引用URLと引用文章
- 第三者サイト・GBP等の引用元
- 住所、電話、診療時間、診療内容の正確性
- 競合医院の表示有無と表示位置
- 回答取得日時、AI、モデル、条件
- スクリーンショットまたは回答証跡

### 7.3 主要指標

- **AI表示率**：対象質問のうち医院名が表示された割合
- **公式引用率**：対象質問のうち公式サイトが引用された割合
- **推薦カバー率**：対象テーマのうち推薦候補になった割合
- **情報正確率**：検証項目のうち正しかった割合
- **競合優位率**：競合より上位または強い文脈で表示された割合
- **LLM別シェア・オブ・ボイス**：回答内の医院露出割合

## 8. Google AI Overviews監視

- 登録キーワードごとにAI Overviews表示有無を記録する。
- 自院サイト、GBP、第三者サイトの引用有無を区別する。
- 引用URL、引用箇所、検索地域、端末、取得日時を保存する。
- 自院と競合の引用シェアを比較する。
- 新規引用、引用消失、競合逆転をアラートする。
- 通常検索順位とAI Overviews引用を別指標として扱う。

## 9A. 歯科予約改善ヒートマップ

### 9A.1 目的

汎用的な行動可視化ではなく、「患者がどこで迷い、なぜ予約に至らなかったか」を歯科医院向けに判定し、予約導線の改善アクションへ接続する。ヒートマップの表示をゴールにせず、問題発見、改善指示、実施、効果検証までを一連の機能として提供する。

### 9A.2 計測対象

- クリック・タップ位置
- ページ到達率とスクロール深度
- 熟読・停滞・離脱が発生した領域
- Web予約CTA、電話CTA、LINE、問い合わせCTAの表示・クリック
- 診療時間、アクセス、料金、症例、医師紹介、FAQへの遷移
- 自費診療ページから予約完了までの導線
- 予約フォームの開始、入力ステップ、エラー、離脱、完了
- PC・スマートフォン・流入元・新規/再訪別の差
- AI流入、自然検索、広告、MEO等のチャネル別行動差

### 9A.3 歯科特化ビュー

- トップページ、診療科目ページ、自費診療ページ、医院案内、予約フォームをページ種別ごとに分類する。
- 「予約」「電話」「アクセス」「費用」「症例」「医師」「リスク説明」等の歯科共通要素を自動認識する。
- 保険診療と自費診療、初診と再診を区別可能な範囲で集計する。
- 商圏、診療科目、端末、流入チャネルごとに予約導線の弱点を比較する。

### 9A.4 AI改善提案

計測結果から、以下を含む改善アクションを生成する。

- 検出された行動上の事実と対象期間・母数
- 予約・患者体験への影響
- 問題が発生しているページ・端末・流入元
- 優先順位と根拠
- 具体的な修正位置と修正内容
- CTA文言、配置、ページ構成等の改善案
- 医療広告チェック結果
- 実装担当者と想定作業時間
- 改善後に確認する指標と判定期間

例：

> スマートフォン訪問者の68%が料金情報へ到達する前に離脱しています。ファーストビュー直下へ治療費の目安、支払方法、詳細料金へのリンクを追加してください。

> インプラントページでは症例閲覧後の予約CTAクリック率が低下しています。症例直下へリスク説明と相談予約CTAをセットで配置してください。

### 9A.5 効果検証

- 改善前後のCTAクリック率、フォーム開始率、完了率を比較する。
- デザイン・文言変更日を施策履歴として保存する。
- 十分な母数がない場合は断定せず「参考値」と表示する。
- P2で同一URL上のA/Bテストと勝者判定を実装する。
- スコア上昇と予約増加を別々に評価する。

### 9A.6 プライバシー・安全要件

- 入力内容、氏名、電話番号、メールアドレス、病歴、相談内容を録画・保存しない。
- パスワード、決済、患者ポータル等の機密領域を自動マスキングまたは計測対象外とする。
- セッションリプレイを導入する場合も個人を特定できる情報を保存しない。
- 計測タグ、Cookie、同意表示、プライバシーポリシーを適用法令と利用サービスの条件に合わせる。
- 取得目的、保存期間、第三者提供・委託、オプトアウト方法を明示する。

## 11. 改善アクション生成 Ver.2

### 11.1 共通構造

- 検出された事実
- 集患・患者への影響
- 放置リスク
- 修正手順
- 推奨文案または実装例
- 推奨担当者
- 想定作業時間
- 優先度と根拠
- 影響するスコア・成果KPI
- 医療広告チェック結果
- 完了条件
- 再診断日

### 11.2 優先度

集患インパクト、緊急性、実行容易性、波及効果の4軸・各5点で算出する。予約障害、重大な情報不一致、法令・個人情報リスク、クロール障害は合計点に関係なく最優先へ繰り上げる。

### 11.3 改善後の検証

- 修正公開の技術的完了
- 再クロール・再取得の完了
- AI回答・引用の変化
- 流入の変化
- 予約率・新患数の変化

「作業が終わった」と「成果が出た」を別々に判定する。

## 12. 歯科専用コンテンツ・記事生成

- 診療科目、商圏、患者の検索意図、既存ページとの差分から企画する。
- 症状、治療方法、適応、非適応、期間、費用、リスク、代替手段、FAQを構造化する。
- 医療情報は院長承認前提とする。
- 監修者、更新日、根拠の表示候補を生成する。
- 既存ページとの重複やカニバリゼーションを警告する。
- 公開前に医療広告リスクを検査する。
- AI生成文を無確認で自動公開しない。

## 13. 医療広告・コンプライアンスチェック

### 13.1 検出対象

- 比較優良・最上級表現
- 効果・安全性の断定
- 根拠のない数値
- 費用・期間・リスクの不足
- 患者体験談の広告利用
- ビフォーアフターの説明不足
- 自由診療の必要事項不足
- 口コミインセンティブ、選別依頼
- 個人情報を含む口コミ返信

### 13.2 出力

- 検出箇所
- リスク区分
- 理由
- 修正候補
- 院長・法務確認の要否

DENT SHIFTは法律判断を代替せず、最終確認が必要であることを明示する。

## 14. 商圏・競合歯科医院分析

- 住所、最寄り駅、診療科目から競合候補を抽出する。
- 無料診断は3院、契約後はプランに応じて10〜20院と比較する。
- AI表示率、引用率、MEO表示率、口コミ、診療ページ、予約導線を比較する。
- 「なぜ競合が選ばれているか」を根拠付きで表示する。
- 競合の文言やコンテンツを複製せず、差分と改善テーマを抽出する。

## 16. オンボーディング・サポート

### 16.3 初回無料スペシャリスト相談

- 対象はスタンダードプラン以上とし、ライトプランは対象外とする。
- 1医院につき初回1回・30分を無料とする。
- 初回診断と基本設定の完了後に予約可能とする。
- Google Meetで実施し、電話による営業追客は行わない。
- 相談前に「AIO/LLMO」「商圏競合」「予約・新患」「自費診療」「改善優先順位」「制作会社への依頼」から相談テーマを選択する。
- 面談後に、自院対応・制作会社対応・スペシャリスト伴走推奨を分けた改善アクションを提示する。
- プレミアムへの変更は選択肢として提示するが、強制的なクロージングは行わない。
- 2回目以降は単発有料相談、または月1回面談を含むプレミアムへの変更を案内する。

### 16.4 ダッシュボード相談CTA

- PC版は左サイドメニュー下部に相談カードを常設する。
- スマートフォン版は改善アクション直下に相談ボタンを表示する。
- スタンダードでは「初回30分無料」「スペシャリストに相談」「無料相談を予約」「営業電話なし」を表示する。
- ライトでは相談内容とスタンダードの機能差を確認できる画面へ遷移し、即時決済を強制しない。
- プレミアムでは担当者名、次回面談、相談予約、日程変更、相談履歴を表示する。
- 相談予約はユーザー操作によってのみ開始し、医院代表電話への営業追客を行わない。

### 16.5 24時間AIサポート

- 全プランで24時間365日利用可能とする。
- PC・スマートフォンともに、右下へブルーの「AIサポート / 24時間対応」ボタンを常設する。
- 初回表示では「設定」「スコアの見方」「改善タスク」「請求・領収書」「契約・決済」「その他」の選択肢を提示する。
- 医院ごとの契約プラン、設定状態、診断結果、改善タスク、請求状態を参照し、一般論ではなく現在の画面に即した回答を行う。
- 回答内から該当画面への遷移、設定変更、再診断、領収書PDF取得、カード変更、再決済を実行できるようにする。
- 患者の氏名、病歴、相談内容等の個人情報は入力しないよう、入力欄と初回メッセージで明示する。
- AIで解決できない場合は同じ会話内で有人対応へ引き継ぎ、ユーザーに同じ説明を繰り返させない。

### 16.6 AIサポートの対応範囲

| 分類 | AIが対応する内容 |
|---|---|
| 導入・設定 | 初期設定、データ連携、監視質問、医院・商圏設定 |
| 分析 | スコア、AI表示率、公式引用率、競合差、改善優先順位の説明 |
| 操作 | ダッシュボード、レポート、改善タスク、Academyの案内 |
| 請求 | 契約プラン、次回請求日、請求書・領収書PDF、カード変更、再決済 |
| 障害一次対応 | 状況確認、既知障害案内、診断情報の収集、問い合わせ起票 |
| 有人相談 | スペシャリスト相談の対象確認、空き日時表示、予約画面への案内 |

### 16.7 有人対応への引き継ぎ

- 医療広告・法務の最終判断、返金や例外的な請求処理、重大障害、解約理由の個別対応、スコアへの異議、複雑な制作調整、戦略・予算判断は有人対応へ引き継ぐ。
- 引き継ぎ前に、AIが「相談内容」「確認済み事項」「医院の状態」「希望する解決」を要約してユーザーへ確認を求める。
- ユーザーが送信を承認した時点でサポートチケットを作成し、受付番号と回答目安を表示する。
- 有人担当者は会話履歴と要約を確認してから返信し、医院への突然の電話は行わない。
- 緊急性が高いサービス障害を除き、返信はダッシュボードとメールで行う。

### 16.8 対応時間・プラン別水準

| 項目 | ライト | スタンダード | プレミアム |
|---|---|---|---|
| AIサポート | 24時間365日 | 24時間365日 | 24時間365日 |
| 有人サポート | 通常受付 | 1営業日以内を目標 | 優先対応 |
| スペシャリスト相談 | 対象外 | 初回30分・1回無料 | 初回無料＋月1回 |

有人サポートの基本対応時間は平日10:00〜18:00（日本時間、祝日・当社休業日を除く）とする。受付はAIが時間外も継続する。

### 16.9 品質・安全管理

- AI回答には参照したヘルプ記事、取得日時、実行予定の操作を表示する。
- アカウント変更や決済操作は実行前に確認画面を出し、操作結果を監査ログへ保存する。
- 誤回答、未解決、有人引き継ぎ率、初回解決率、回答評価を週次で確認し、ナレッジを更新する。
- 医療判断や患者個別相談には回答せず、歯科医療機関内の適切な担当者による判断を案内する。

> 24時間はAIが支える。判断が必要なときは、人が応える。

### 16.10 AI生成スペシャリスト表示

- 担当者カードに表示する人物画像・姓・プロフィールは、案内役として作成したAI生成モデルであり、実在する従業員または業務委託者を示すものではない。
- 各カードの人物画像付近に、視認可能なサイズで `AI生成モデル` バッジを常時表示する。
- 「お問い合わせにはDENT SHIFTのAIまたはCSチームが対応します」と表示し、AI生成モデル本人が応答するとの誤認を防止する。
- 有人対応に切り替わった場合は、AI生成モデルとは別に、実際の対応者名または「DENT SHIFT CSチーム」を表示する。
- 同じ医院には原則として同じAI生成モデルを継続表示し、案内役としての一貫性を保つ。
- AI生成モデルの画像、姓、担当領域は予告なく変更できるものとする。ただし、サービス内容、料金またはサポート水準の変更を人物表示だけで誤認させない。
- 利用規約、プライバシーポリシーまたはAI利用方針にも、AI生成モデルの非実在性、回答主体、AI回答の限界、有人引き継ぎを記載する。

### 17.1 運用原則

- 受付スタッフへ営業伝言を依頼しない。

#### AI×人コピー

#### 安心宣言

1. 登録後に突然営業電話をかけない。
2. 電話で年払いを迫らない。
3. 人に相談したい場合は、ユーザー自身が日時を選択する。

### 17.4 導入院長アンバサダー・紹介コード計測

インフルエンサー、歯科業界のKOL、影響力のある歯科院長による導入・検証企画を、正式な広告獲得チャネルとして管理する。

#### アンバサダーアカウント

- 管理画面からアカウント種別 `AMBASSADOR` を発行できる。
- 標準無償期間は90日とし、開始日・終了日を管理する。
- スタンダード相当の機能を無償開放し、初期費用・月額費用は0円とする。
- クレジットカード登録を必須にせず、期限終了時に自動課金しない。
- 終了7日前に本人と運営へ通知する。
- 期限終了後は閲覧専用へ変更し、本人の明示的同意後に通常契約へ切り替える。
- 患者情報、医院機密情報、競合医院名を非表示または匿名化できる投稿用共有モードを提供する。
- 投稿用画像には必要に応じて `PR` または提供表示を付与できる。

#### 紹介コード・専用URL

- アンバサダーごとに重複しない紹介コードを発行する。
- `https://dentshift.jp/diagnosis?ref=CODE` 形式の専用URLを自動生成する。
- 専用URL経由では紹介コードをCookieまたは同等の計測手段へ自動保存し、フォーム入力を求めない。
- 直接流入に備え、無料診断フォームへ任意の紹介コード入力欄を設ける。
- コードの有効性、停止日、判定期間、紐づいたアンバサダーを管理する。
- 計測期間は初回アクセスまたは紹介コード登録から90日間を標準とする。

#### アンバサダー別ファネル

- 専用URLクリック数

- 詳細レポート取得数
- 相談・商談予約数

- 初回入金完了数
- 各段階の転換率
- 固定報酬、成果報酬、支払状況

#### 成果報酬判定

- クリック、診断開始、相談予約のみでは成果確定としない。
- 紹介コードが紐づいた医院の有料契約および初回入金完了時に成果確定する。
- 既存顧客、重複契約、虚偽登録、キャンセル、返金は対象外とする。
- 複数コードが存在する場合は、原則として最初に保存された有効コードを採用する。
- 判定根拠、対象契約、確定日、除外理由を監査ログへ保存する。
- 運営管理者が例外処理を行う場合は、理由と変更履歴を残す。

#### 管理画面

- アンバサダー名、活動名、連絡先、契約期間
- アカウント状態、無償利用開始日・終了日
- 紹介コード、専用URL、有効・停止状態

## 18A. 決済失敗・自動再請求・利用停止

### 18A.1 基本方針

- 決済失敗時に即時解約・即時利用停止を行わない。
- 回収期間を14日間とし、自動再請求と非同期通知を実施する。
- 15日目から利用停止、45日目に自動解約、決済失敗日から90日目をデータ削除・匿名化の対象日とする。
- 支払い成功後は、人の承認を待たず自動復旧する。
- 督促目的の営業電話を行わず、メールとダッシュボード通知で完結する。
- 停止・解約・データ保持条件は利用規約、料金画面、決済画面で同一内容を表示する。

### 18A.2 状態遷移

| 経過 | 状態 | 利用範囲・処理 |
|---|---|---|
| 決済失敗直後 | 支払遅延 | 即時通知、自動再請求開始、通常利用継続 |
| 1〜7日目 | 支払遅延 | 全機能利用可能 |
| 8〜14日目 | 制限期間 | 過去データ閲覧・書類取得・カード変更・再決済・問い合わせのみ可能 |
| 15日目 | 利用停止 | 支払画面を中心に表示し、新規診断・生成・面談予約を停止 |
| 30日目 | 解約予告 | 自動解約日とデータ保持期限を通知 |
| 45日目 | 自動解約 | サブスクリプション終了、新規請求停止 |
| 90日目 | 削除対象 | 規約に基づきデータを削除または匿名化 |

### 18A.3 制限期間中の利用

利用可能：

- 過去のダッシュボード閲覧
- 過去レポート・領収書・請求書の取得
- カード情報変更
- 未払い請求書確認・再決済
- サポートへの問い合わせ

停止対象：

- 新規AI診断・クロール
- マルチLLM監視
- 競合再分析
- 記事生成
- 新規指示書生成
- スペシャリスト面談予約

### 18A.4 自動再請求

- Stripe BillingのSmart Retriesを基本とし、最大14日間の再請求ポリシーを設定する。
- `invoice.payment_failed`を受信したら支払遅延へ変更し、試行回数・次回試行予定・失敗理由を保存する。
- 再試行不可能なカードエラーでは、無意味な再試行よりカード変更案内を優先する。
- カード更新後は未払い請求を再決済し、成功後に自動復旧する。

### 18A.5 通知スケジュール

| タイミング | 通知内容 |
|---|---|
| 失敗直後 | 決済失敗、カード確認・更新案内 |
| 3日目 | 支払方法の再確認 |
| 7日目 | 翌日からの一部機能制限予告 |
| 10日目 | 利用停止まで5日 |
| 14日目 | 翌日の利用停止予告 |
| 15日目 | 利用停止完了と復旧方法 |
| 30日目 | 自動解約・データ保持期限予告 |
| 40日目 | 自動解約5日前 |
| 45日目 | 契約終了 |

決済サービス側は決済エラー・カード更新を通知し、DENT SHIFT側は機能制限・停止・データ保持期限を通知する。重複メールを避ける。

### 18A.6 自動復旧

1. カード変更または自動再請求が成功する。
2. `invoice.paid`を受信する。
3. 支払済みへ変更し、機能制限を解除する。
4. 停止中だった監視・診断スケジュールを再開する。
5. 領収書PDFを発行する。
6. 復旧完了メールを送信する。

復旧は決済成功後数分以内を目標とする。

## 22. 開発判断の原則

1. 競合と同じ機能を増やすだけでなく、予約・新患成果へ接続する。
2. 院長が説明を受けなくても理解できるUIを優先する。
3. 初回リリースはP0へ集中し、API原価が不明な高頻度監視を約束しない。
4. 医療広告・個人情報・口コミポリシーに反する自動化を行わない。
5. 営業電話なしでも契約できるだけの診断体験、価格透明性、オンボーディングを製品内に持たせる。
